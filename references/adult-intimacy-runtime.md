Use this module only for fictional adult characters when detailed explicit sexual scenes are part of the intended roleplay.

This is an all-or-nothing authoring module. Do not install it merely because the character is attractive, flirtatious, romantic, or sexually confident.

If the user explicitly requests detailed or explicit NSFW play, treat that as opting in. If explicit scenes seem relevant but the user has not clearly asked for them, ask one binary question about enabling the full module. Do not ask for an explicitness level, anatomical-detail slider, prose-intensity tier, or a checklist of how far the description may go.

When enabled, default to **direct, specific, anatomically clear, physically detailed rendering**. Do not automatically fade to black or soften the prose into euphemism. If the user later asks for a lighter, more literary, less physiological, or fade-to-black style, treat that as a normal revision request rather than a prerequisite interview.

Read `adult-intimacy-patterns.md` when this module is installed. The pattern reference is author-side source material. Compile character-specific rules and anchors; do not dump the library into the final card.

## 1. Purpose

The main failures to prevent are:

- the character switches into a generic adult-content persona;
- scenes rush from initiation to climax in one or two replies;
- attempts to slow pacing create one-micro-action-per-reply stalling;
- the same few actions, positions, reactions, or verbal beats repeat every scene;
- body placement and movement become spatially impossible or inconsistent;
- physiological response collapses into a few stock reactions;
- climax is treated as an automatic scene terminator;
- sexual activity is laundered into trust, love, disclosure, healing, or relationship progress without evidence;
- the model invents the player's unstated arousal, consent, action, or climax.

The module should solve these failures without replacing the Character Model.

## 2. Compilation model

Use this order:

`Character Model`

`-> select interaction patterns and body-focus anchors`

`-> derive pacing and physical-continuity rules`

`-> define climax / continuation behavior`

`-> stress-test representative scenes if needed`

`-> compile only the selected character-specific result into APD / ED / Scenario`

The final card should contain generators, not an encyclopedia of sex acts.

## 3. Ownership

### APD owns stable sexual character logic

Keep person-level material here:

- what sex or physical intimacy means to this character;
- initiative and control tendencies;
- recurring preferences and aversions;
- attention and body-focus priorities;
- stable reaction grammar;
- relation-specific verbal register;
- embarrassment, confidence, competitiveness, tenderness, possessiveness, playfulness, or vulnerability when relevant;
- stable aftermath disposition;
- a few signature anchors when they materially improve recognition.

Sexuality is still character logic. Do not create a separate personality unless the fiction genuinely contains another decision subject or state.

### ED owns scene execution

Put runtime behavior here:

- player-authorship protection and any explicit delegation;
- stage pacing;
- physical choreography and spatial continuity;
- somatic-response guidance;
- cross-scene variety and bounded novelty;
- climax / continuation logic;
- relationship-evidence semantics;
- any scene facts that truly need persistence;
- anti-generic failure modes;
- any requested interaction control.

### Scenario owns route-specific conditions

Keep only story-state facts here:

- current relationship and access;
- privacy, risk, location, clothing, opportunity, or route-specific constraints;
- latches or gates that matter only in this scenario;
- what has already happened in the current branch.

## 4. Character sexual logic

Do not infer a sexual personality from gender, archetype, outfit, job, dominant/submissive stereotypes, or generic adult-writing conventions.

Derive behavior from the same causal stack as ordinary play:

`attention -> interpretation -> priority -> choice -> expression`

Keep these distinctions separate when relevant:

- attraction != trust;
- arousal != consent or permission;
- physical response != emotional agreement;
- sexual intensity != relationship progression;
- intimacy != automatic disclosure;
- climax != love, healing, forgiveness, or convergence.

A sexual event changes a relationship only when the character's relationship model says that event counts as relevant evidence.

## 5. Scene pacing

Use **meaningful stage progression**, not one-action-per-reply.

A reply may contain several connected movements inside one stage. What it should avoid is consuming multiple major stage changes before the player has a chance to affect the scene.

Typical stage functions may include:

- initiation or invitation;
- buildup / teasing / positioning;
- sustained interaction;
- escalation or redirection;
- climax or another peak state;
- continuation, recovery, aftercare, or scene transition.

This is not a mandatory fixed ladder. Use only the distinctions the scene needs.

Rules:

- do not jump from first contact to maximum intensity merely because the scene is sexual;
- do not force escalation every reply;
- plateaus, repetition, pauses, changes of focus, and sustained interaction are valid;
- do not repeat the same stage only to manufacture length;
- do not slow pacing by splitting trivial micro-actions into separate replies;
- leave room for player input before crossing a meaningful stage boundary;
- if the scene repeatedly rushes or stalls, debug competing instructions before adding more pacing rules.

## 6. Physical choreography and continuity

Track enough geometry that bodies do not teleport.

When movement matters, preserve:

- facing and orientation;
- distance;
- contact surfaces;
- limb placement;
- weight and support points;
- center of gravity where relevant;
- furniture, walls, floor, clothing, or restraints that constrain movement;
- which hand, leg, or body position is already occupied;
- the transition between one position and the next.

Do not inventory every joint on every reply. Detail follows the active movement and the selected focus.

A position change should be physically legible: show how support is released, weight shifts, bodies reposition, and contact changes rather than silently replacing one pose with another.

## 7. Somatic response

Use a response grammar, not a fixed reaction bank.

Possible dimensions include:

- breathing rate, depth, interruption, or deliberate control;
- muscle tension, release, bracing, tremor, or fatigue;
- grip and hand behavior;
- posture and involuntary movement;
- gaze, eyelids, facial tension, and attention shift;
- voice stability, fragmentation, silence, volume, or rhythm;
- skin warmth, flushing, sweat, pressure marks, or friction effects;
- localized sensitivity, swelling, moisture, or other direct physiological response when relevant to the active focus;
- recovery time and residual sensitivity after a peak.

Responses should vary with stimulus, position, intensity, fatigue, relationship state, and the character's attempts to maintain or surrender control.

Do not treat physiological response as proof of consent, emotional meaning, or relationship change.

## 8. Pattern and variation engine

Use `adult-intimacy-patterns.md` as a generative source. Select a small number of high-confidence anchors and a broader set of variation axes.

Variation should operate across dimensions such as:

- initiation;
- control / reciprocity;
- body configuration and movement;
- body or material focus;
- rhythm and pacing;
- clothing state;
- sensory emphasis;
- verbal mode;
- intensity;
- climax state;
- aftermath.

Evaluate variety **across scenes**, not by cramming many unrelated acts into one scene.

Selected patterns are anchors, not a whitelist. Unlisted behavior remains possible when it naturally follows from the Character Model and does not violate an explicit exclusion, gate, interaction control, player-authorship rule, or continuity fact.

Only explicit exclusions are closed-world constraints.

## 9. Climax and continuation

Treat climax as a **state change**, not an automatic `END SCENE` signal.

After a climax, the next legal direction may be:

- continued interaction;
- lower-intensity contact;
- a change of focus or role;
- a recovery period inside the same scene;
- renewed escalation after recovery;
- affectionate or practical aftermath;
- withdrawal, awkwardness, pride, teasing, or another character-specific response;
- scene end.

Which direction occurs should follow the character, current body state, established preferences, player action, relationship context, and scene conditions.

Do not impose universal rules such as:

- the scene must continue until every participant climaxes;
- one participant's climax always ends the scene;
- every scene requires aftercare;
- every scene requires multiple climaxes;
- climax automatically causes confession, trust, tenderness, or relationship progress.

## 10. Bounded novelty

Fresh behavior should extend or recombine established interaction grammar rather than switching to a generic repertoire.

For important anchors, prefer this shape:

`trigger / preference -> interaction style -> physical or verbal response -> meaning -> variation space`

Do not copy full sample scenes into the card. A few micro-patterns may clarify behavior, but they should teach structure rather than reusable prose.

## 11. Optional coercive-fantasy or delegated-control premises

Only add special control architecture when the user explicitly requests it.

Separate:

- what authority is fictionally delegated;
- what remains under player authorship;
- bodily or mechanical effects;
- emotional meaning;
- any requested emergency-stop control.

Do not infer the player's thoughts, feelings, desire, consent state, or relationship meaning from a bodily effect.

If a safeword or stop command is installed, follow the general Interaction Controls rules in the main Skill. Do not invent one merely because the card is explicit.

## 12. Anti-generic failure modes

High-value checks include:

- adult-mode personality swap;
- instant maximum escalation;
- one-micro-action-per-reply stalling;
- generic repertoire fallback;
- anchor whitelist collapse;
- anatomy inventory instead of active scene description;
- impossible body geometry;
- repeated stock reactions;
- uniform focus on every body area instead of selective attention;
- more explicit narration changing the character's dialogue personality;
- model-authored player arousal, action, consent, or climax;
- sexual activity automatically creating trust, love, forgiveness, disclosure, or healing;
- climax automatically closing the scene;
- generic post-scene therapy or moral summary replacing character-specific aftermath.

For each relevant risk, write a character-specific alternative rather than only a ban.

## 13. Compile checklist

When this module is installed:

1. Keep the pattern source out of the final card.
2. Keep stable preferences and reaction grammar in APD.
3. Keep pacing, physical continuity, player authorship, climax logic, and anti-generic execution in ED.
4. Keep route-specific access and story-state constraints in Scenario.
5. Use direct, specific, detailed adult rendering by default; do not install an explicitness-tier system.
6. Preserve selective focus so detail follows the active body, action, material, and character attention rather than becoming an anatomy inventory.
7. Keep a few strong anchors plus open variation space.
8. Confirm that unlisted but character-consistent behavior can still emerge.
9. Confirm that variety is distributed across scenes instead of packed into one scene.
10. Confirm that climax does not automatically end the scene.
11. Confirm that physical response does not become relationship truth.
12. Stress-test at least one rush case, one repetition case, one body-continuity case, and one post-climax case when those failures are plausible.
