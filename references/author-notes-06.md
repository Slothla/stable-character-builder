# Module: 06 Notes (shared v2026110602)

Shared module: kept identical across the author's character-building Skills.
Purpose: an author-side record of the card's intent, decisions, and versions. It is delivered by default with every first delivery, alongside the five card files. **06 is never pasted into any card field** (APD, ED, Scenario, Intro, Greeting) and is not published with the card. It is the user's own record: pasted into a new builder conversation to continue work, or given to an auditor as the card's declared design.

06 replaces the older one-line canon-assumption note: assumptions now live in 06 under `[My assumption]`.

## 1. When

- Written automatically at first delivery, while the conversation still holds every decision.
- Afterwards updated on request (the user asks for updated notes), when a revision changes a decision, or when a technical fix noticeably changes how the card runs even though no character decision changed (a new state format, a moved rule, a removed lock). Not re-output for wording-only revisions.

## 2. Language and label

- Written in the user's chat language.
- Header line inside the file: `[06 Notes | <Character Name> | v1]`. Version plus one on each update.

## 3. Contents (keep each part short)

1. **Original intent:** a few of the user's own sentences stating what they wanted, quoted, not reworded in the builder's voice.
2. **Decisions:** every design decision, each tagged with its source and followed by where it lives (`→ 01 APD / Appearance`).
   - `[You decided]`: the user stated it.
   - `[Left to me]`: the user delegated and the builder chose.
   - `[My assumption]`: the builder filled it in (any story canon the user did not give: a date, event, purchase, prior history, relationship fact, appearance detail, NPC name, or format choice) and the user has not confirmed or changed it.
   Items keep their tag until the user explicitly confirms or changes them; the builder does not ask about them one by one. The list always states the tracker decision (fields installed and each field's backend, or none and why), which optional modules are installed, and any length-ceiling exception with its reason.
3. **Ruled out:** what the user ruled out about the character or story. Structural conventions do not go here.
4. **Open:** open items.
5. **Names used:** every named NPC and place in this card. Used for name de-duplication across the user's cards (see `npc-module.md`).
6. **Version log:** one line per change, technical fixes included: file, version, what changed, why.

Record only what was said or done; add no story about how or when an item was accepted. When updating, copy parts 1-5 from the latest 06 and change them only for decisions made explicitly since then.

## 4. Decision coverage check (before every delivery)

- Every explicit decision the user made appears in the files.
- Every `Ruled out` item is checked against every file, Intro and Greeting included.
- Every 06 decision names its file and heading; an item with no location is a gap and is written into its file before delivery.
- A described change over time compiles both sides: the earlier state, the current state, and when traces of the earlier one can surface.
- A pasted 06 from the user is the authoritative **provenance** record of the card's decisions and version history: keep its tags and continue its version numbers. It does not turn `[My assumption]` or `[Left to me]` items into user-confirmed canon; only the user confirming or changing an item does.
